## 5. Defects found — all measured, none invented

**A. Save payload is wrapped, contract doc says unwrapped — MEDIUM, needs a decision.**
Actual: `{"graph":{"version":1,"nodes":[…],"edges":[…]}}` on `PATCH /api/workflows/:id`; create sends `{"name":…,"graph":{…}}`.
`docs/workflow-graph-contract.md` §5 states the frontend hands over `{ "version": 1, "nodes": [...], "edges": [...] }` **verbatim**. Either the doc or the API is wrong. Backend obviously accepts the wrapper, so this is a **documentation** defect — but it will mislead the Change-Streams work. Owner: Mahak (doc) + Swathi (confirm intended API).

**B. Graph canvas clips its leftmost node — MINOR, cosmetic.**
`.node-preview__canvas` = 502.4 px wide, `overflow: hidden`, no fit-view on mount. Node `task-1` at x=406.6 → **22.2 px clipped** (renders "ASK / harge payment"). Persists at 1440 px, so not a narrow-window artifact.

**C. Minimap overlaps a node; "Apply condition" below the fold — MINOR.**
Minimap (200×150) intersects `task-2`. At 900 px height the details panel's `Apply condition` button sits at y≈1059, under the fold, and the panel doesn't scroll independently.

**D. Only Condition nodes can be added from the UI — MEDIUM (functional gap).**
The only add control is "Add condition node". There is no way to add a `trigger` or `task` node, so a user can never build a workflow from scratch — they must start from the seed demo graph. Connects to defect E.

**E. Workflow creation is gated on a graph you cannot yet create — MEDIUM (UX dead-end for a new user).**
`+ Create workflow` fails with `No workflow graph is available. Open Node Preview and prepare a graph before saving.` — but Node Preview only ever holds the seed demo graph, which itself is invalid (unconfigured condition nodes, duplicate `true` branch). Three consecutive save attempts were rejected:
1. `No workflow graph is available…`
2. `Condition node "New condition" is missing a valid clause configuration…`
3. `graph: Condition node "condition-5" has multiple true branches` (400)
Success only after configuring both condition nodes and removing a duplicate `true` edge.

**F. Editor mislabels the workflow + reload loses editing context — MINOR.**
Editing "Gate 26 Oct" shows `Editing saved workflow: Untitled workflow`. After F5 the editor falls back to the seed demo graph rather than the workflow being edited — the user must go Workflows → Edit workflow again. Combined with B this means the canvas a user sees after reload is *not* their saved graph.

**Nit.** `App.tsx:20` runs `console.log('API key configured:', …)` on every render — 14 identical lines per load. Remove before the console evidence is considered clean.
