## 2. Headline findings

1. **Event-triggered executions would multiply with instance count.** Every backend process opens its own change stream on `BusinessEventModel` and dispatches on every matching insert, with no claim. Horizontal scaling today duplicates work rather than sharing it.
2. **A running execution cannot be distinguished from a dead one.** There is no lease, no heartbeat, and `currentNodeId` is written `null` and never updated.
3. **The 100 requests / 15 min limiter is per-process and in-memory.** Any HTTP-level concurrency test will hit the limiter long before the runtime becomes the bottleneck, and the effective limit scales with instance count.
4. **Retry remains inert.** The `retry` field is validated and stripped from the handler payload (decision D1) but never acted on. Decision D3 keeps execution synchronous, which parks D2, D4, D5 and D6.

## 3. Retry/DLQ minimum viable path

Option A, recommended and awaiting approval: retry only by error code with default deny, maximum 3 dispatches, deterministic exponential backoff capped at 30 s, attempt count persisted *before* dispatch, and exhaustion recorded as `failed` + `attempts: N` + `deadLetteredAt`. DLQ is a tenant-scoped query over `deadLetteredAt`, not a service. Side-effecting actions stay non-retryable until an idempotency contract exists.

Required before any code: **D2** (schema fields) and **D6** (exhaustion semantics). Eleven acceptance criteria are defined in §2.5 of the plan.

## 4. Concurrency testing readiness

- **Counting:** harness counter counts an execution active from first node dispatch to last node settlement, and reports `maxActive`. The database proxy (`status` in `running`/`compensating`) under-counts and must not be used to claim overlap.
- **Stages:** L0 in-process (done), L1 isolated local replica set, L2 isolated staging, L3 multi-instance, L4 soak. Nothing above L0 runs against the shared database.
- **Stop conditions:** any failure, `maxActive < requested`, unexpected 429, p95 > 5 s, RSS growth > 50 %, rising change-stream lag, any duplicate execution at L3.
- **Split with Mahak:** she owns API-level integration and frontend contract correctness for history/summary and the WebSocket scenarios; this task owns runtime concurrency and retry/DLQ design. The fan-out finding affects her integration order and should be reviewed together.
